# Bar activity: what the host and the stage must give it (ruling 38, contract 10)

The bar (`src/minigames/bar/`) is played IN the room through the stage. It draws nothing and makes no canvas view (`make_view()` returns null). It touches no engine file.
It talks to the world through a port object, `ctx["world"]` in `setup` (a `WorldThings`, see `src/contracts/world_things.gd`; without one it uses a recording stub, `activity.world()`).

## What the bar tells the world

| Call | When | Content |
|---|---|---|
| `set_things(arr)` | every update and press | `things()`: `bar_glass` (frames 0 empty, 1 / 2 / 3 layers, 4 overflow, 5 tipped; `layers` = hex colours of the layers, an extra key for the stage to tint with; `at` slides to the customer on a served drink; absent while the glass is gone) and `bar_order` (the bubble, frame = the ingredient shown now, present only during the demonstration). Each: `{id, sprite, at [x, z], sector, size [w, h] m, frame, y (centre height m), anchor}`. |
| `people(id, state, t0, dur)` | each phase | `customer`: waiting, happy, frown, hands_up. `bartender`: idle, clap, hands_up, raise_glass. The stage must know `frown` and `raise_glass` (the brief lists waiting, happy, impatient, clap, hands_up). |
| `feedback(thing, kind, t)` | each press and serve | `bar_glass` tick or cross; `bar_counter` glow (a drink served, the payoff). |
| `piece_on(piece, t)` | a drink served (and at `begin` for those already served) | `bar_shelf_<i>`, one back-shelf glass per served drink. |
| `piece_pulse(piece, t, bars)` | the payoff | all four `bar_shelf_*`. |

`piece_on`, `piece_off` and `piece_pulse` are not in the signatures the coordinator listed for `world_things.gd`; the shelf glasses are pieces so they are needed. The host maps them to the stage actions
`piece_on` / `piece_pulse` that `StoryStage` already has. `src/contracts/world_things.gd` here is my own copy (the cloakroom branch writes the same file): keep theirs and add the three piece methods.

## Map, sheets, layout

- Test map: `tests/fixtures/bar_scene/bar_room.json` (a `StoryMap` that loads clean): sector `bar_room`; pieces `bar_counter`, `bar_back_shelf`, `bar_shelf_0..3` (billboard things with a `piece` id); waypoint `bar_view`
  at (0, 0.5) facing +z; the customer stands at (-1.2, 1.4), the bartender at (0.6, 2.9). A real rave map needs the same ids and its own coordinates: override per theme in `content/bedsit/themes.json` `bar.<theme>.layout`
  (keys in `BarData.LAYOUT`: sector, glass_at, customer_glass_at, bubble_at, sizes, shelf_prefix, counter_piece).
- Sheets (PLACEHOLDERS, generated by `tools/minigames/make_bar_sheets.gd`): `assets/story/bar_test/sprites/bar_glass_<theme>.png` (6 frames of 64 x 96) and `bar_order_<theme>.png` (4 frames of 128 x 128).
  Real art replaces them; the glass sheet's layer colours are the theme's first three ingredients, so the stage should tint a layer from `layers`.
- The map's `piece` ids need manifest entries in the scene's art (`assets.piece(id)`), not written here.

## H-bar-1: pictograms on the controls (src/run/run_activity_input.gd, src/run/run_minigame_host.gd `_show_controls`)

`BarActivity.controls()` returns `{id, label: "", icon: <ingredient id>, shape, color: "#rrggbb"}`. `RunActivityInput._draw` draws only `labels[i]` as text, so the four strip buttons stand blank (the brief wants
silhouette plus colour, no words). Wanted: `_show_controls` copies `shape` and `color` per control into the layer, and `_draw` draws `BarDraw.texture(shape, Color(color))` centred in the button, about 70 % of the short side,
nearest filtered, and no text when `label == ""`. `tools/minigames/bar_demo.gd` draws them itself to show the intended look.

## H-bar-2: remembered order across leaving and returning (optional)

Remembered in `BarActivity._memory` (static, keyed by theme and the run's wallet instance): lasts while the app runs. To keep it in the save, `RunProgress` would store `raves.<theme>.bar = {served, recipe}` and pass
it in the request config; the activity side is small once the host passes it.

## Not built here (the stage, package A8)

Drawing the things, directing the crowd actors, feedback marks at the thing's screen point, the pad-strip morph, the view test "three moments, each thing's rectangle inside the strip and at least 48 px tall".
`tools/minigames/bar_demo.gd` is a flat DATA PREVIEW of the same calls, not the stage.
