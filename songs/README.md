# Song packs

A song pack is one folder: `level.json` plus an `audio/` directory holding four aligned stems.
The full contract is PRD section 9 (`docs/PRD.md`); the essentials:

- `level.json` (`schema_version` 1): `bpm` 174, `time_signature` [4, 4], `ticks_per_beat` 960,
  `song_offset_ms`, `duration_ticks` (bars x 3840, bar 1 = tick 0), `seed`, `stems` (relative
  paths for `kick`, `snare`, `bass`, `other`), `battlefield`, `roster`, `rules`, `sections`
  (contiguous, covering tick 0 to `duration_ticks`), `notes` (`id`, `tick`, `lane` kick/snare/bass,
  `type` tap/hold, bass holds carry `duration_ticks`) and `enemy_events` (`id`, `tick`, `action`).
- `event_seconds = song_offset_ms / 1000 + tick * 60 / (bpm * ticks_per_beat)`.
- Every stem starts at the same timeline point, has the same sample rate and the same length.
  Nothing starts at or after `duration_ticks`; holds end inside the song; a lane never overlaps itself;
  a kick and a snare never share a tick; kicks and snares keep clear of a bass hold's press moment.

## Placeholder packs

| Pack | Global bars | Seed | Notes |
| --- | --- | --- | --- |
| `dev_dnb/` | 513-832 (the DnB section, 320 bars) | 27 | density-limited chart: 80 kicks, 32 snares, 40 bass holds |
| `test_16/` | 513-528 (16 bars) | 7 | `--all-hits`: every usable hit is charted, for tests |

Both were generated by `tools/make_song_pack.py` from the owner's 174 BPM MIDI clip library
(`Three_Movements_174BPM_MIDI_Clips_and_Assembly_Guide.zip`): the tool walks
`01_Assembly_Placements.csv` for the bar range, takes kicks (GM 36) and snares (GM 38) from the
`13_Drums` clips and bass notes from `11_Sub` (falling back to `09_Reese`, then `08_Growl`, for any
bar without a sub placement), keeps a seeded, evenly spread, strong-beat-preferring subset as the
chart, mirrors 85% of it as enemy events, and takes sections from `02_Section_Roadmap.csv`.

**The audio is synthesised placeholder sound** (numpy sine/noise drums, a sine sub, hats and a quiet
pad), rendered from every hit in the MIDI so it follows the arrangement. It exists only so the game
can be built and tested against correctly aligned stems; replace the four Ogg files with the owner's
Ableton stem exports (same timeline start, same sample rate, equal length) when they are available.

## Regenerating

Extract the zip into a fresh, empty folder outside the project (it is downloaded data, so keep it
separate and run the tool with `python -I`):

```bash
mkdir -p /tmp/clips
python -I -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).extractall(sys.argv[2])" \
    ~/Downloads/Three_Movements_174BPM_MIDI_Clips_and_Assembly_Guide.zip /tmp/clips
LIB=/tmp/clips/Three_Movements_174BPM_Clip_Library
```

Then, from the project root (ffmpeg and ffprobe must be on PATH; numpy is the only package needed):

```bash
python -I tools/make_song_pack.py --library "$LIB" --out songs/dev_dnb --bars 513-832 --seed 27 \
    --level-id dev_dnb --title "Dev: DnB section"

python -I tools/make_song_pack.py --library "$LIB" --out songs/test_16 --bars 513-528 --seed 7 \
    --level-id test_16 --title "Test: 16 bars" --all-hits
```

Output is deterministic for the same library, arguments and seed. Useful options:
`--kicks-per-bar`, `--snares-per-bar`, `--bass-per-bar` (maximum average charted notes per bar;
defaults 0.25 / 0.1 / 0.125), `--enemy-accuracy` (default 0.85), `--sample-rate` (default 48000),
`--keep-wav` (keep the intermediate WAVs next to the Ogg files). Run `--help` for the full list.
